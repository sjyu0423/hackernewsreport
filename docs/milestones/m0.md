## Implementation notes

### Article identity

- Canonical URL: lowercase host, strip tracking params (`utm_*`, `fbclid`, `gclid`, …), drop fragment, normalize trailing slash.
- Stable `articles.id`: first 32 hex chars of SHA-256(canonical_url).
- Cross-source duplicates share one article row; membership is recorded in `article_sources`.

### Content extraction

- Skips HN discussion URLs (comments are never used as article body).
- Validates public http(s) destinations and every redirect hop.
- Enforces response size limits and text-like Content-Types.
- Respects robots.txt when `QWENNEWS_RESPECT_ROBOTS=true`.
- HTTP 401/403/407/429/451 → `blocked`; other failures → `failed` / `skipped`.
- Title, URLs, and metadata are always retained on extraction failure.

### SQLite

Schema initialized idempotently via `python -m qwennews init-db`:

- `articles`
- `article_sources`
- `collection_runs`
- `collection_run_sources`
- `schema_meta`

Upserts merge richer fields (HN score/comments, successful extraction text) without wiping good data on later failures.

### CLI / config

| Command | Purpose |
| --- | --- |
| `python -m qwennews init-db` | Create DB + schema |
| `python -m qwennews collect` | Collect all enabled sources |
| `python -m qwennews collect --source hackernews` | Single-source collect |
| `python -m qwennews recent --hours 24` | Recent articles |
| `python -m qwennews stats` | DB / run statistics |

See `.env.example` for `QWENNEWS_*` variables. No API keys required.

## Known limitations / M1 recommendations

1. **No scheduler yet** — M1 should add a simple hourly runner (cron or APScheduler) that invokes `collect` and computes deltas from `collection_runs` / `last_seen_at`.
2. **Exact URL dedupe only** — same story on different domains still creates multiple rows; semantic dedupe belongs in M2.
3. **Extraction quality is heuristic** — BeautifulSoup main-content heuristics are intentionally simple; M1/M2 may adopt a stronger extractor if needed.
4. **OpenAI feed is large** — rely on `QWENNEWS_RSS_LIMIT` to bound ingestion.
5. **TechCrunch / paywalled bodies** — metadata is stored even when full text is blocked; this run extracted successfully under current limits/robots policy.
6. **No change-detection for “meaningfully changed” HN scores in reports** — storage retains updated scores; hourly delta reporting is an M1 concern.
7. **Response size limiting uses Content-Length + post-decode length** — fully streamed early-abort for chunked responses without Content-Length can be hardened further in M1 if needed.
