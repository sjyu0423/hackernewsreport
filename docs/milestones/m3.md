# Milestone 3 — Automated Hourly News Reporting

## Goal

Run the full QwenNews workflow automatically on a Mac mini:

`collect → sync stories → analyze → hourly report`

Also support an independent once-daily briefing. No dashboard, cloud inference, fine-tuning, or mobile app.

## CLI

```bash
# Full hourly cycle (collection + sync + analyze + report)
python -m qwennews run-hourly
python -m qwennews run-hourly --max-analyze 5 --notify
python -m qwennews run-hourly --skip-collect --skip-analyze   # report-only

# Independent daily briefing
python -m qwennews run-daily
python -m qwennews run-daily --as-of 2026-11-15T12:00:00Z

# Orchestration status (watermarks, lock, recent runs)
python -m qwennews status
```

Exit codes: `0` success (including empty / duplicate-window skip), `1` failed cycle, `3` lock busy.

## Startup / shutdown (manual)

```bash
# Ensure Ollama is running with the configured model
ollama serve          # if not already a login item
ollama list           # confirm qwen3:4b (or QWENNEWS_OLLAMA_MODEL)

# One-shot hourly
cd /absolute/path/to/HackerNewsReport
source .venv/bin/activate
python -m qwennews run-hourly --max-analyze 5

# Inspect
python -m qwennews status
ls data/reports/
```

There is no long-lived Python daemon. Stop automation by unloading the LaunchAgent (below). Kill a stuck run with normal process tools; the advisory lock releases when the process exits (stale PID recovery is also implemented).

## Mode-specific report state

- Per-mode watermarks live in `report_watermarks` (`hourly` / `daily`).
- Per-mode story publication marks live in `story_report_state`.
- Schema **v5** adds durable `article_processing_state` + `story_processing_state` for backlog-safe drains.
- Hourly publication must not suppress daily (and vice versa).
- Hourly watermarks advance only when the active backlog is fully drained **and** the report persisted.
- Failed writes, missing Ollama, failed collection, and interruptions do not advance watermarks.
- Articles discovered after the cycle cutoff are not marked reported by that cycle.
- Same-window daily duplicates are skipped (`duplicate_window_skipped`).

Legacy `stories.last_reported_at` is still updated for M2 compatibility but is **not** used to gate the other mode.

## M3.1 outcomes (hourly)

| Outcome | Meaning |
| --- | --- |
| `empty_success` | No active backlog; nothing to publish |
| `no_significant_updates` | Backlog drained / analyzed, but nothing met report criteria |
| `backlog_remaining` | Cap or partial drain left pending/failed/ready work — **not** a true empty |
| `success` | Non-empty report published and backlog drained |
| `ollama_unavailable` / `analyze_failed` / `collect_failed` / `report_persist_failed` | Failed; watermark not advanced |

`max_analyze` only limits work **per cycle**. Remaining eligible articles stay queued and are processed on later runs without being discarded by the watermark.

## Scheduling (macOS LaunchAgent)

Prefer launchd over a Python polling loop.

### Generate (does not install)

```bash
python scripts/generate_launchagent.py              # hourly
python scripts/generate_launchagent.py --daily --time 07:00
python scripts/generate_launchagent.py --both
python scripts/validate_launchagent.py packaging/launchd/generated/com.qwennews.hourly.plist
python scripts/validate_launchagent.py packaging/launchd/generated/com.qwennews.daily.plist
```

The generator writes absolute paths for Python, project root, working directory, and logs. The committed `.plist.template` files keep placeholders only. Daily uses `StartCalendarInterval` in the Mac's local timezone (`QWENNEWS_DAILY_LOCAL_TIME` / `--time`).

### Install / enable (explicit user action required)

```bash
mkdir -p ~/Library/LaunchAgents
cp packaging/launchd/generated/com.qwennews.hourly.plist \
   ~/Library/LaunchAgents/com.qwennews.hourly.plist
cp packaging/launchd/generated/com.qwennews.daily.plist \
   ~/Library/LaunchAgents/com.qwennews.daily.plist

launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.qwennews.hourly.plist
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.qwennews.daily.plist
```

### Status

```bash
launchctl print gui/$(id -u)/com.qwennews.hourly
launchctl print gui/$(id -u)/com.qwennews.daily
python -m qwennews status
tail -f data/logs/hourly.stdout.log data/logs/daily.stdout.log
```

### Test run (without waiting for the interval)

```bash
launchctl kickstart -k gui/$(id -u)/com.qwennews.hourly
launchctl kickstart -k gui/$(id -u)/com.qwennews.daily
# or:
python -m qwennews run-hourly --max-analyze 5
python -m qwennews run-daily --skip-analyze
```

### Disable / uninstall

```bash
launchctl bootout gui/$(id -u)/com.qwennews.hourly
launchctl bootout gui/$(id -u)/com.qwennews.daily
rm -f ~/Library/LaunchAgents/com.qwennews.hourly.plist \
      ~/Library/LaunchAgents/com.qwennews.daily.plist
```

**M3/M3.1 do not install or activate LaunchAgents.** Do that only after explicit approval.

### Sleep / wake behavior

- Hourly: `StartInterval=3600`, `ThrottleInterval=1800`, `KeepAlive=false`.
- Daily: `StartCalendarInterval` + `ThrottleInterval=3600` (limits wake catch-up bursts).
- After sleep, launchd may fire once when eligible — QwenNews does **not** loop to catch up missed hours.
- Overlapping hourly/daily runs share one advisory file lock (`data/locks/orchestrate.lock`).

## Daily report

- Independent of hourly watermarks and story marks.
- Configure local delivery time via `QWENNEWS_DAILY_LOCAL_TIME` (LaunchAgent calendar) and `QWENNEWS_DAILY_TIMEZONE` (status/docs helper).
- Reuses cached analyses.
- Duplicate same `as_of` + `window_start` publications are skipped.
- Hourly and daily orchestration never run Qwen concurrently (shared lock).

## Ollama availability (login sessions)

QwenNews **detects** a stopped Ollama server; it does **not** auto-start duplicate servers or modify Login Items / launch services.

Recommended operator setup (manual, once):

1. Install Ollama and pull `qwen3:4b`.
2. Prefer the Ollama app as a normal user Login Item (System Settings → General → Login Items), **or** keep `ollama serve` running under your user session.
3. Verify before enabling agents:

```bash
curl -s http://127.0.0.1:11434/api/tags
python -m qwennews status   # includes ollama.ok / model_present
```

If `ollama.ok` is false, hourly/daily runs exit with `ollama_unavailable` and do not advance watermarks.

## Delivery

- Markdown under `QWENNEWS_REPORT_DIR` (default `data/reports/`).
- Optional macOS notification (`QWENNEWS_NOTIFY_ON_SUCCESS` or `--notify`): short count/summary only.
- Notification failure never invalidates a persisted report.
- No email, cloud APIs, or automatic browser tabs.

## Resource safety

| Knob | Env | Default |
| --- | --- | --- |
| Inference timeout | `QWENNEWS_OLLAMA_TIMEOUT` | 180s |
| Max analyses / cycle | `QWENNEWS_MAX_ANALYZE_PER_CYCLE` | 20 |
| HTTP connect/read | `QWENNEWS_*_TIMEOUT` | 5 / 20 |
| HTTP retries | `QWENNEWS_HTTP_MAX_RETRIES` | 2 (capped ≤5) |
| Single inference worker | (hardcoded) | concurrency=1 |

## Troubleshooting

**Ollama unavailable**

```bash
curl -s http://127.0.0.1:11434/api/tags
ollama pull qwen3:4b
```

Orchestration outcome: `ollama_unavailable` — watermark not advanced.

**Connectivity / empty feeds**

- Check `source_errors` in `python -m qwennews status` / orchestration run records.
- All sources failing with zero articles → `collect_failed` (not an empty success).

**Lock busy**

- Another hourly/daily run holds `data/locks/orchestrate.lock`.
- Wait for completion or confirm the holder PID is dead (stale locks are recoverable).

## Report file locations

- Markdown: `data/reports/briefing_{hourly|daily}_YYYYMMDDTHHMMSSZ.md`
- SQLite: `data/qwennews.db` (`reports`, `report_watermarks`, `story_report_state`, `orchestration_runs`)
- Logs (when using LaunchAgent): `data/logs/hourly.*.log`

## Limitations

- Ollama must stay up across login (Login Item or equivalent); QwenNews will not launch it.
- Daily calendar times follow the Mac's local timezone; `QWENNEWS_DAILY_TIMEZONE` is informational for status/helpers.
- HN score-only changes remain UNCHANGED and do not force re-analysis.
- Unit tests never call live HTTP or Ollama.
