# W0 — QwenNews Public Website Foundation

**Branch:** `website-w0-foundation` (from `milestone-4-2-production-reliability` @ `a33b08c`)  
**Scope:** routing, layout, navigation, design system, static-export plumbing, docs  
**Out of scope:** W1–W5 full page implementations, commits, push, deploy

## Architecture

The public site lives in a standalone `website/` package. It is **not** the private `dashboard/` app.

| Concern | Choice |
| --- | --- |
| Framework | Next.js 15 App Router + TypeScript |
| Styling | Tailwind CSS + CSS variables |
| Output | `output: "export"` → `website/out/` |
| Hosting target | GitHub Pages (project site or custom domain) |
| Data | Static fixtures only (`website/content/fixtures/`) |
| Runtime APIs | None (no Ollama / FastAPI / SQLite) |

### Routes

| Path | Purpose | W0 state |
| --- | --- | --- |
| `/` | Product overview | Foundation copy |
| `/demo/` | Interactive briefing | Shell + W1 placeholder |
| `/how-it-works/` | Architecture explanation | Pipeline summary + W2 placeholder |
| `/engineering/` | Benchmarks / decisions | Principles + W3 placeholder |
| `/under-the-hood/` | Optional technical depth | W4–W5 placeholder |

### Separation from private product

- Does not import from `dashboard/` or `qwennews/`.
- Does not read `data/*.db`.
- Does not require `.env` for build or preview.
- GitHub Actions workflow is manual (`workflow_dispatch`) only.

## Design system

Dark-mode-first technology editorial:

- **Ink backgrounds:** `#0b0d12` → elevated panels
- **Accents:** blue `#7b8cff` and violet `#9a86ff` (subtle, not glow-heavy)
- **Typography:** Source Serif 4 (display), Source Sans 3 (body), IBM Plex Mono (labels)
- **Motion:** short fade/rise; disabled under `prefers-reduced-motion`
- **Layout:** spacious `shell`, sticky accessible header, semantic landmarks

## Local development

```bash
cd website
npm install
npm run dev          # http://localhost:3000
npm run typecheck
npm run lint
npm run build        # static export to out/
npm run verify:export
```

### Subpath smoke test (GitHub Pages style)

```bash
cd website
NEXT_PUBLIC_BASE_PATH=/hackernewsreport npm run build
NEXT_PUBLIC_BASE_PATH=/hackernewsreport npm run verify:export
# Optionally serve out/ behind a /hackernewsreport prefix with any static server
```

Optional absolute metadata:

```bash
NEXT_PUBLIC_SITE_URL=https://example.github.io/hackernewsreport \
NEXT_PUBLIC_BASE_PATH=/hackernewsreport \
npm run build
```

## GitHub Pages publishing plan

1. Keep site builds isolated under `website/`.
2. Set Pages source to **GitHub Actions** when authorized.
3. Run `.github/workflows/website-pages.yml` manually (`workflow_dispatch`).
4. Pass `base_path` (`/hackernewsreport` for the observed GitHub repo name) or empty for a custom domain at root.
5. Pass `site_url` when Open Graph absolute URLs are required.
6. Do **not** enable push-based deploys until explicitly authorized.
