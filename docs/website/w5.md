## GitHub Pages configuration steps (manual)

Pages settings cannot be changed from this W5 branch without authorization. Operator steps:

1. On GitHub → **Settings → Pages**.
2. Set **Source** to **GitHub Actions**.
3. Confirm the environment `github-pages` exists (created on first workflow deploy).
4. Open **Actions → Website Pages (manual)** → **Run workflow**.
5. Keep defaults:
   - `base_path` = `/hackernewsreport`
   - `site_url` = `https://sjyu0423.github.io/hackernewsreport`
6. Approve the deploy job if environment protection rules require it.
7. Verify `https://sjyu0423.github.io/hackernewsreport/` loads Home and that `/demo/`, asset URLs under `/hackernewsreport/_next/`, and OG tags resolve.

Workflow file: `.github/workflows/website-pages.yml`

- `workflow_dispatch` only (no push / PR deploy)
- Builds `website/` with Node 20 (`npm ci`, typecheck, lint, test, build, verify)
- Uploads **only** `website/out`
- Does **not** need Ollama, Python, or SQLite
- Permissions: `contents: read`, `pages: write`, `id-token: write`

## Exact deployment approval steps

1. Human review of W5 diff on `website-w5-release`.
2. Merge to the GitHub default branch only when authorized (this W5 work stops before merge/push).
3. Manually run **Website Pages (manual)** on GitHub Actions.
4. Confirm Pages source = Actions.
5. Smoke the published URL (home + demo + engineering).

## Rollback a failed deployment

1. In GitHub Actions, re-run an earlier successful **Website Pages (manual)** workflow (redeploy prior artifact), **or**
2. Fix forward on a new commit and re-run the manual workflow.
3. If Pages must be taken down temporarily: Settings → Pages → disable / change source (operator decision).
4. Do **not** force-push history unless explicitly requested.
